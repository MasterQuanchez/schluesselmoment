The Recommendation

Yes, adopt it — but scope it honestly and harden it incrementally. A thin, explicit SDLC encoded as skills + specs is the right shape for governed, repeatable AI-assisted delivery. Call it what it is: structured prompts and conventions (living policy), not a mechanically-enforced system. Start with 4 skills, not 10.

The One Thing to Do First Run one real feature end-to-end through plan → implement → review → test → sync-to-devops, then measure what broke. Not a hello-world. A real, small, scoped feature with a real ADO work item. Document every friction point vs. every real issue caught. That evidence earns team buy-in.
AGREE Where the Council Agrees
  • Markdown skills are legitimate. Versionable, diffable, auditable — good properties for enterprise DT.
  • Handoff + wikilinked specs give narrative traceability without tooling lock-in.
  • Human checkpoints at phase boundaries are necessary for compliance, even if they cost throughput.
  • This is process glue, not automation. The team must understand it as such.
  • Cursor coupling is a real vendor risk but acceptable at this stage.

BLIND SPOTS What the Peer Reviews Caught
  • Incentives & ownership. No skill assigns a human owner. Under deadline pressure, the path of least resistance is to skip the pipeline. Nothing detects this.
  • Partial adoption. DT spans people who won't use Cursor, legacy systems, non-agent workflows. The architecture is silent on these cases.
  • Cost of the process. Token spend, senior time curating specs, ceremony overhead — none measured or bounded.
  • AI-specific governance. Data handling, model usage policies, prompt audit trails for regulated contexts.
  • Exception paths. Hotfixes, spikes, and legacy glue don't fit the pipeline. Without documented fast-paths, teams invent ad-hoc ones that break traceability.
Conditions for Success
  1. Start with 4 skills, not 10. Plan, implement, review, test. Add discover, council, simplify, design only after the core loop is proven.
  2. Assign a human owner per skill accountable for accuracy and adoption.
  3. Document a fast-path (hotfix/spike) with lighter ceremony but equivalent audit trail.
  4. Lint the spec graph. Broken wikilinks and missing frontmatter should fail CI.
  5. Measure from week one: lead time (plan → merged PR) and spec-to-ADO sync accuracy.
